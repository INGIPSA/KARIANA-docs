    KARIANA Assistant Window UI Redesign#

    For Claude: REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

    Goal: Redesign the KARIANA Assistant Window to match the Figma design (file key JG6nAlfSv1UgLXqsmU6Mwa), covering header, toolbar, welcome screen, chat messages, mode selector, input, history panel, log bar, model dropdown, and a new options/choice cards feature.

    Architecture: Modify existing Slate widgets in Source/UnrealAssistantIntegration/. The layout restructure is primarily in SKarianaChatPanel::Construct() and BuildHeader(). Most changes are visual/layout — widget classes stay the same, but their internal construction changes. One new widget class (SKarianaChoiceCards) is added for the options/choice feature.

    Tech Stack: Unreal Engine 5.7 Slate UI (C++), KarianaBrand color system, FKarianaMarkdownStyle brushes.

    Figma Reference: https://www.figma.com/design/JG6nAlfSv1UgLXqsmU6Mwa/KARIANA-UI — use get_screenshot with specific node IDs when visual reference is needed during implementation.

    Verification: After each task, build in Rider (Build > Build Solution) and visually verify in UE editor. No automated UI tests exist for Slate widgets.

    Goal: Replace the current header (status dot + "KARIANA" + connection text + model selector + settings/history buttons) with the Figma design: hamburger menu left | "Claude - Opus 4.5" centered with chevron | provider label + status dot right.

    Step 1: Redesign BuildHeader()#

    Replace the current BuildHeader() method. The new header is a single horizontal row:

    [≡ hamburger] ---- [Model Name ∨] ---- [Provider Status●]

    Left: Hamburger button (≡) that triggers OnToggleHistory() (replaces the old history toggle button).

    Center: Model display text + chevron-down icon. Clicking opens model selector dropdown (Task 9). Use existing ModelComboBox but restyle it as a flat text button with chevron.

    Right: Provider label (e.g. "AWS", "Claude", "Local") + colored status dot. The provider comes from Proxy->GetCurrentProvider() or settings. The status dot uses existing StatusConnected/StatusWarning/StatusError colors based on connection state.

    Implementation notes: - Remove the old enable checkbox (EnableCheckBox), "KARIANA" brand label, clear chat button, and settings button from the header — these move to the toolbar (Task 2) - Header height: ~40px, dark background (BgBase or BgRaised) - Hamburger icon: Use text "≡" (U+2261) in a 24x24 button, or create a simple 3-line icon via FSlateBrush - Status dot: 8x8 rounded ellipse, colored by connection state - Provider label: Small text (TextSecondary, 9pt), right-aligned before status dot

    Step 2: Add provider/status tracking members#

    Add to SKarianaChatPanel.h: - TSharedPtr<STextBlock> ProviderLabel — displays "AWS", "Claude", etc. - TSharedPtr<SBorder> StatusDot — colored connection indicator - FText GetProviderDisplayText() const — returns current provider name - FSlateColor GetStatusDotColor() const — returns color based on bridge connection state

    The status dot color logic: - Green (StatusConnected): Bridge exists and IsProcessReady() returns true - Yellow (StatusWarning): Bridge exists but not ready (connecting/initializing) - Red (StatusError): No bridge or bridge reports disconnected

    Step 3: Remove old header elements#
