    Per-Turn Chat Refactor — Backend/Frontend Split Contract#

    Date: 2026-05-21 Integration branch: refactor/per-turn-chat-message Sub-branches: refactor/per-turn-backend, refactor/per-turn-frontend Parent plan: 2026-05-21-per-turn-chat-message.md

    Two parallel agents land separate PRs into the integration branch. This document is the contract both agents code against — neither agent should change anything specified here without the other being notified.

    File ownership#

    Backend agent (refactor/per-turn-backend)#

    Owns: - Source/UnrealAssistantIntegration/Public/KarianaChatSession.h - Source/UnrealAssistantIntegration/Private/KarianaChatSession.cpp - Source/UnrealAssistantIntegration/Public/KarianaChatTypes.h (struct shape, enum values) - Source/UnrealAssistantIntegration/Public/KarianaAssistantProxy.h - Source/UnrealAssistantIntegration/Private/KarianaAssistantProxy.cpp - Source/UnrealAssistantIntegration/Public/KarianaClaudeCodeBridge.h - Source/UnrealAssistantIntegration/Private/KarianaClaudeCodeBridge.cpp - Source/UnrealAssistantIntegration/Public/DaemonIOThread.h - Source/UnrealAssistantIntegration/Private/DaemonIOThread.cpp - Source/UnrealAssistantIntegration/Private/KarianaConversationStore.cpp - Source/UnrealAssistantIntegration/Public/KarianaConversationStore.h - Source/UnrealAssistantIntegration/Private/UnrealAssistantIntegration.cpp (proxy→session bindings only) - Source/UnrealAssistantIntegration/Private/Widgets/SKarianaChatPanel.cpp — only the binding block in Construct() at lines ~170-322. Frontend owns the layout/widget tree elsewhere in this file. - Content/Python/kariana_agent_daemon.py (image event step_index emit) - Content/Python/backends/bedrock_daemon_adapter.py (same) - Content/Python/tests/parity/** (test scenarios + assertions)

    Frontend agent (refactor/per-turn-frontend)#

    Owns: - Source/UnrealAssistantIntegration/Private/Widgets/SKarianaChatMessage.h - Source/UnrealAssistantIntegration/Private/Widgets/SKarianaChatMessage.cpp - Source/UnrealAssistantIntegration/Private/Widgets/SKarianaStepsWidget.h - Source/UnrealAssistantIntegration/Private/Widgets/SKarianaStepsWidget.cpp - Source/UnrealAssistantIntegration/Private/Widgets/KarianaStepRowFactory.h (new) - Source/UnrealAssistantIntegration/Private/Widgets/KarianaStepRowFactory.cpp (new) - Source/UnrealAssistantIntegration/Private/Controllers/KarianaMessageController.h - Source/UnrealAssistantIntegration/Private/Controllers/KarianaMessageController.cpp - Source/UnrealAssistantIntegration/Private/Widgets/SKarianaChatPanel.cpp — only the layout/widget tree and visual code outside the binding block. Backend owns the binding block.

    Shared / coordination required#

    • SKarianaChatPanel.cpp is split. Backend touches binding code; frontend touches layout. Keep edits to disjoint line ranges. If a conflict arises, frontend agent rebases.
    • KarianaChatTypes.h is backend-owned but frontend reads. Backend must not break the public shape mid-refactor without notifying integration.

    Stable interface contract (DO NOT CHANGE without coordination)#

    Data shape (in KarianaChatTypes.h)#

    struct FKarianaChatStep {
    int32 StepIndex;
    FString ToolName;
    FString StepText;     // Text Claude wrote BEFORE this tool call
    FString StepPreview;
    EKarianaStepStatus Status;
    FDateTime StartTime, EndTime;
    double DurationSeconds;
    TArray<FString> ImagePaths;  // Step-attached images (from take_editor_screenshot etc)
};

struct FKarianaChatMessage {
    FGuid MessageId;
    EKarianaChatRole Role;        // User | Assistant | Error | UserInputRequired
    FString Content;              // Trailing text AFTER the last tool call (or full text if no tools)
    TArray<FKarianaChatStep> Steps;  // One entry per tool call this turn, in order
    TArray<FString> ImagePaths;   // Message-level images (non-tool-attached)
    EKarianaChatMessageState State;
    FString ModelUsed;
    FDateTime Timestamp, ResponseStartTime;
    int32 McpToolCount;
    // Backend MAY drop `bIsIntermediateTurn` and `EKarianaChatRole::Processing`
    // usage. Frontend MUST not depend on `Processing` for new code — render same
    // shape regardless of role being Processing or Assistant.
};

    Invariant: One FKarianaChatMessage per assistant turn. Steps[] in arrival order. Content is everything after the last tool.

    Session API (backend)#

    // Lifecycle
FKarianaChatMessage& BeginAssistantTurn(const FString& Model);
void AppendToStreamingMessage(const FString& Chunk);  // appends to current msg's Content
void AddToolUseStep(const FString& ToolName, const FString& StepText, int32 StepIndex);
  // — appends a new Step; snaps current msg's Content into the new step's StepText
  //   if daemon StepText is empty; clears msg.Content (post-step trailing buffer).
void AddImageToCurrentStep(const FString& ImagePath, int32 StepIndex);
  // — attaches image to Steps[StepIndex].ImagePaths if step exists; falls back
  //   to message-level ImagePaths if StepIndex is INDEX_NONE or invalid.
void AddImageToCurrentMessage(const FString& ImagePath);  // legacy, message-level
void BeginNextTurn(const FString& Model);  // finalize current msg as Complete + Assistant; create new Assistant streaming msg
void CompleteStreamingMessage(const FString& FullContent);
void FailStreamingMessage(const FString& ErrorText);
void CancelStreamingMessage();

    Removed (callers must update): - BeginAssistantMessage → use BeginAssistantTurn - BeginResponseSegment → no-op, remove - EndProcessingSegment → no-op, remove - BeginNextTurnSegment → use BeginNextTurn

    Delegate signatures (backend → frontend)#

    FOnChatMessageAdded     OnMessageAdded(const FKarianaChatMessage&);
FOnChatMessageUpdated   OnMessageUpdated(const FKarianaChatMessage&);
FOnChatStepAdded        OnStepAdded(const FGuid& MsgId, const FKarianaChatStep&);
FOnChatStepUpdated      OnStepUpdated(const FGuid& MsgId, const FKarianaChatStep&);
FOnChatStepImageAdded   OnStepImageAdded(const FGuid& MsgId, int32 StepIndex, const FString& Path);  // NEW
FOnChatCleared          OnCleared();
FOnChatStreamingStateChanged OnStreamingStateChanged(bool bStreaming);

    Frontend hooks all of these on the controller. When OnMessageAdded fires for an Assistant-role streaming message, the controller creates ONE widget. Subsequent OnStepAdded/OnStepUpdated/OnStepImageAdded/OnMessageUpdated update the SAME widget by MessageId.

    Proxy → Session bindings (in SKarianaChatPanel.cpp binding block)#

    Backend owns the binding block. After refactor: - OnStreamingChunk → Session->AppendToStreamingMessage(chunk) (no segment routing) - OnProcessingSegmentEnd → REMOVED (no-op event, unsubscribe) - OnTurnRestart → Session->BeginNextTurn(model) - OnToolUse → Session->AddToolUseStep(tool, step_text, step_index) - OnImage(path, step_index) → Session->AddImageToCurrentStep(path, step_index) - OnResponseGenerated → Session->CompleteStreamingMessage(full) - OnError → Session->FailStreamingMessage(err)

    The OnProcessingSegmentEnd delegate on the proxy itself stays (other consumers may use it) — just the session-side handler is dropped.

    Daemon wire protocol changes#

    Image events gain step_index field:

    // Before
{"type": "image", "id": msg_id, "path": "/path/to.png"}
// After
{"type": "image", "id": msg_id, "path": "/path/to.png", "step_index": 3}
// step_index is the index of the step the image belongs to (0-based).
// If image is not tool-attached, omit step_index (or set to -1).

    Backend agent updates daemon + bedrock adapter + ClaudeCodeBridge JSON parsing + AssistantProxy OnImage delegate signature.

    Widget contract (frontend)#

    SKarianaChatMessage::Construct for Assistant/Processing roles renders this vertical stack:

    For each Step in Steps[]:
  - If Step.StepText non-empty: markdown block
  - Step row (from KarianaStepRowFactory::BuildStepRow)
  - For each ImagePath in Step.ImagePaths: SKarianaImagePreview
If Content non-empty:
  - Markdown block (trailing text)
For each ImagePath in message-level ImagePaths (non-step-attached):
  - SKarianaImagePreview
Footer:
  - Per-turn stats: "Time: Xs ∣ Tools: Y"
  - On the final turn after stream-complete: extra line "Total: Σs ∣ Y across N turns"
  - Hidden while bIsStreaming

    Public widget API for incremental update (called by controller):

    void UpdateContent(const FString& NewText);              // for trailing Content streaming
void UpdateState(EKarianaChatMessageState);
void AppendStep(const FKarianaChatStep& Step);           // new step row
void UpdateStep(const FKarianaChatStep& Step);           // step status/timing change
void AddStepImage(int32 StepIndex, const FString& Path); // step-attached image
void AddImage(const FString& Path);                      // message-level image
void SetToolCount(int32 Count);
void SetSessionTotal(int32 TurnCount, double TotalSeconds, int32 TotalTools);  // only set on the final-turn widget; hides if any negative

    KarianaStepRowFactory::BuildStepRow(const FKarianaChatStep&) -> TSharedRef<SWidget> extracted from current SKarianaStepsWidget::BuildStepRow. Returns the visual row with accent bar, status icon/throbber, activity label, timing label, click-to-expand detail.

    Controller responsibilities (frontend)#

    After refactor FKarianaMessageController has: - TMap<FGuid, TSharedPtr<SKarianaChatMessage>> MessageWidgets — one per turn - TMap<FGuid, TSharedPtr<SKarianaUserInputPrompt>> UserInputWidgets - (deleted) ActiveStepsWidget, ActiveStepsContainer, ActiveStepsMessageId, StreamingAssistantContainer, StreamingAssistantMessageId, MoveActiveStepsWidgetToEnd - (deleted) Processing→Assistant upgrade branch in OnMessageUpdated

    Step events forward to the message widget directly:

    OnStepAdded(MsgId, Step)   → MessageWidgets[MsgId]->AppendStep(Step)
OnStepUpdated(MsgId, Step) → MessageWidgets[MsgId]->UpdateStep(Step)
OnStepImageAdded(MsgId, Idx, Path) → MessageWidgets[MsgId]->AddStepImage(Idx, Path)

    Persistence migration (backend)#

    KarianaConversationStore load-time migration: - Scan loaded messages array. - For each (Processing-with-Steps, Assistant) consecutive pair: merge into ONE Assistant message — keep Steps from the Processing, set Content from the Assistant, sum McpToolCount. - Drop standalone Processing messages with no following Assistant (cancelled/incomplete turns). - Migration is idempotent — running on already-migrated data is a no-op. - Bump on-disk format version (FKarianaConversationData.SchemaVersion) if one exists; otherwise migrate transparently every load.

    Compaction (backend)#

    FKarianaChatSession::Compact(int32 KeepRecent = 4) — default bumped 6 → 4.

    • Update existing multi_turn_agent_loop.json if its assertions assume the old split shape
    • C++ compile via UnrealBuildTool against the integration branch (typecheck only — no editor run required from agent)

    Frontend agent#

    • C++ compile
    • Manual reasoning trace through the widget render path with synthetic message data (no editor run required from agent)

    Integration smoke (orchestrator runs)#

    • Editor opens, sends a 4-tool prompt
    • Observe text-tool-text-tool-text interleaving in a single bubble
    • Cancel mid-stream — verify no orphan spinners
    • Load an old transcript saved before this PR — verify migration produces single turn widgets

    Workflow rules#

    1. Both agents work on their own worktrees + branches. No cross-edit to files outside their ownership list.
    2. Each agent opens its own PR targeting refactor/per-turn-chat-message (NOT developer).
    3. Each PR triggers .github/workflows/claude-code-review.yml. Agent addresses any actionable feedback.
    4. No merge to developer without orchestrator review of integration branch + editor smoke test.
    5. Coordination edits to shared files (SKarianaChatPanel.cpp, KarianaChatTypes.h) require either pre-coordination via this doc or a follow-up rebase before integration merge.
    6. Tests must be green in each PR before that PR merges to integration.
