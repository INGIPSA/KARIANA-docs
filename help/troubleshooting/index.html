    Troubleshooting#

    Solutions for common KARIANA issues.

    Account & Sign-In#

    "Failed to proxy request to Clerk FAPI: fetch failed" on the sign-in page#

    Symptoms: The sign-in card at app.kariana.ai/sign-in shows the error:

    Failed to proxy request to Clerk FAPI: fetch failed

    when you submit your password or request an email verification code. A private/incognito window may sign in normally, while your regular browser keeps failing.

    Cause: One or more cookies accumulated in your browser for app.kariana.ai are being forwarded to the authentication upstream and cause the request to fail before it leaves our infrastructure. This happens most often for accounts that have signed in many times across deploys or Clerk instance migrations.

    Solution — clear cookies for app.kariana.ai only:

    1. Open the browser DevTools (F12 or Ctrl+Shift+I / Cmd+Option+I).
    2. Go to the storage panel:
    3. Firefox: Storage tab
    4. Chrome / Edge / Brave: Application tab
    5. Expand Cookies and select https://app.kariana.ai.
    6. Select all rows → right-click → Delete All.
    7. Reload /sign-in and sign in again.

    You only lose your session on app.kariana.ai; all other sites are unaffected.

    Alternatives if you can't open DevTools:

    • Open a private/incognito window and sign in there.
    • Use Clear browsing data scoped to app.kariana.ai only (Chrome: Settings → Privacy → Site settings).

    If the error persists after clearing cookies, contact support with the time of the failed attempt so we can correlate with server logs.

    Connection Issues#

    "UE_NOT_CONNECTED" Error#

    Symptoms: Claude reports it cannot connect to Unreal Engine.

    Solutions:

    1. Verify UE is running
    2. Open Unreal Engine
    3. Load or create a project

    4. Check that the editor is fully loaded

    5. Check Remote Control plugin

    6. Go to Edit > Plugins
    7. Search for "Remote Control"
    8. Ensure both plugins are enabled

    9. Restart UE if you just enabled them

    10. Verify ports 

      # Check if ports are listening (Windows)
netstat -an | findstr "30010"
netstat -an | findstr "9877"

    11. Check firewall

    12. Allow UE through Windows Firewall

    13. Allow ports 30010, 30020, 9877

    14. Restart services

    15. Close Claude Desktop
    16. Close Unreal Engine
    17. Restart both

    "Connection Refused"#

    Symptoms: Socket connection fails immediately.

    Solutions:

    1. Check KARIANA plugin is enabled
    2. Edit > Plugins > KARIANA

    3. Enable and restart

    4. Verify socket server started

    5. Check Output Log for: [KARIANA] Socket server started

    6. Check port availability 

      netstat -an | findstr "9877"
      If another app uses 9877, change the port in settings.

    Remote (Extended) Tools Not Working#

    Symptoms: Core tools (blueprints, actors, etc.) work but extended tools (cinematics, physics, PCG, patterns, etc.) fail or the remote MCP server (port 8002) crashes on startup.

    Solutions:

    1. Enable Remote Control Web Server
    2. Go to Edit > Project Settings
    3. Search for Remote Control Web Server
    4. Enable Auto Start Web Server ✅
    5. Enable Auto Start Web Socket Server ✅
    6. Verify port is 30010 (HTTP) and 30020 (WebSocket)

    7. Restart Unreal Engine

    8. Enable Remote Execution

    9. In Project Settings, search for Remote Control
    10. Under Security, enable:
      • Enable Remote Python Execution ✅
      • Allow Console Command Remote Execution ✅

    11. Under Python Remote Execution, enable:

      • Enable Remote Execution? ✅

    12. Disable passphrase enforcement (or configure it)

    13. In Remote Control > Security, check Enforce Passphrase for Remote Clients
    14. If enabled with 0 passphrase entries, all connections to port 30010 will be blocked

    15. Either uncheck it, or add a passphrase and configure your MCP client accordingly

    16. Verify port 30010 is listening 

      netstat -an | findstr "30010"
      If port 30010 is not listening after enabling the settings, restart Unreal Engine.

    Why does this only affect extended tools?

    KARIANA uses two MCP servers. The core server (port 8001) communicates through KARIANA's own socket server (port 9877), which starts automatically with the plugin. The remote server (port 8002) routes through Unreal's Remote Control API (port 30010), which requires these project settings to be enabled.

    Intermittent Disconnections#

    Symptoms: Connection works sometimes, drops randomly.

    Solutions:

    1. Increase timeout 

      {
  "env": {
    "KARIANA_TIMEOUT": "60"
  }
}

    2. Check system resources

    3. Close unnecessary applications

    4. Check CPU/memory usage

    5. Disable sleep mode

    6. Prevent computer from sleeping during use

    Tool Errors#

    "Actor Not Found"#

    Symptoms: Commands fail with actor not found error.

    Solutions:

    1. Use exact name 

      "Select the actor named 'Cube_1'" (not just 'Cube')

    2. Check World Outliner

    3. Verify the actor exists

    4. Note the exact name

    5. Refresh actor list 

      "List all actors in the level"

    "Material Not Applied"#

    Symptoms: Material command succeeds but object doesn't change.

    Solutions:

    1. Verify actor has mesh

    2. Empty actors can't have materials

    3. Check material exists 

      "List all materials"

    4. Specify material slot 

      "Apply M_Red to element 0 of the cube"

    Fab/glTF Asset — Textures Not Displaying#

    Symptoms: Asset imported from Fab (glTF format) appears untextured in viewport, despite material and textures being correctly assigned. You may see warnings like *Texture samples ... as Linear Color (these are informational, not the cause).

    Root Cause: glTF assets often store UV maps on channel 1 or 2, while UE5 materials default to channel 0.

    Diagnosis:

    1. Open the Static Mesh in the editor
    2. Click the UV dropdown in the toolbar
    3. Check which UV channel has valid, non-overlapping UVs (usually channel 1)

    Fix — Step 1: Adjust UV channel on existing material (try first)

    1. Open the Interchange MaterialInstance assigned to the mesh
    2. If the parent material exposes a TexCoord parameter, change it to the correct UV channel
    3. Recompile and check if textures display

    Fix — Step 2: Create standalone material (last resort)

    If the Interchange parent material (MI_Default_Opaque_DS / M_Default) won't compile or can't be edited:

    1. Create a new base Material (no Interchange dependency)
    2. Add a TextureCoordinate node with the correct UV channel index
    3. Connect it to the UVs input on ALL texture samplers
    4. Wire textures: BaseColor → Base Color, ORM → R=AO / G=Roughness / B=Metallic, Normal → Normal
    5. Set sampler types: BaseColor=Color, ORM=Linear Color, Normal=Normal
    6. Recompile and assign to the mesh

    Tip

    Only BaseColor/albedo textures should have sRGB enabled. Normal, Roughness, Metallic, AO, and Height maps should always be Linear (sRGB off).

    "Blueprint Compilation Failed"#

    Symptoms: Blueprint operations fail to compile.

    Solutions:

    1. Check for errors 

      "Check BP_MyActor for compilation errors"

    2. Verify nodes are connected

    3. Execution pins must be connected

    4. Check variable types

    5. Ensure type compatibility

    Performance Issues#

    Slow Response Times#

    Symptoms: Commands take long to execute.

    Solutions:

    1. Reduce actor count
    2. Many actors slow down operations

    3. Organize into folders

    4. Disable real-time rendering

    5. Window > Viewports > Realtime off

    6. Close unnecessary editor tabs

    7. Check background processes

    High Memory Usage#

    Symptoms: UE or system runs out of memory.

    Solutions:

    1. Restart UE periodically

    2. Clear undo history

    3. Edit > Editor Preferences > Undo

    4. Reduce undo buffer size

    5. Purge unused assets

    6. Content Browser > right-click > Asset Actions > Fix Up Redirectors

    Plugin Issues#

    Plugin Not Visible#

    Symptoms: KARIANA doesn't appear in plugins list.

    Solutions:

    1. Verify installation location
    2. Engine: [UE]/Engine/Plugins/Marketplace/KARIANA/

    3. Project: [Project]/Plugins/KARIANA/

    4. Check plugin file exists

    5. KARIANA.uplugin should be present

    6. Verify UE version

    7. KARIANA requires UE 5.7+

    Plugin Crashes UE#

    Symptoms: Unreal Engine crashes when plugin loads.

    Solutions:

    1. Check dependencies
    2. Enable Remote Control first

    3. Enable Python Script Plugin

    4. Verify plugin integrity

    5. Re-download and reinstall

    6. Check logs

    7. [Project]/Saved/Logs/
    8. Look for crash info

    Claude Desktop Issues#

    "No Tools Available"#

    Symptoms: Claude doesn't see KARIANA tools.

    Solutions:

    1. Check config file location

    2. Windows: %APPDATA%\Claude\claude_desktop_config.json

    3. Verify JSON syntax 

      # Validate JSON
python -m json.tool claude_desktop_config.json

    4. Restart Claude Desktop

    5. Fully close (check system tray)

    6. Reopen

    7. Check MCP logs

    8. View > Developer > MCP Logs

    MCP Server Won't Start#

    Symptoms: Server process fails to launch.

    Solutions:

    1. Check Python installation 

      python --version
uvx --version

    2. Install dependencies 

      pip install kariana-mcp

    3. Check command path

    4. Verify uvx or python is in PATH

    Common Error Messages#

    Error Cause Solution
    TIMEOUT Operation took too long Increase timeout, simplify request
    INVALID_PARAMS Wrong parameter types Check tool documentation
    PERMISSION_DENIED Operation not allowed Check context (editor vs PIE)
    ASSET_NOT_FOUND Asset path incorrect Verify path in Content Browser
    SOCKET_ERROR Network issue Check ports, restart services

    {

  }
}

    Sending us a support bundle#

    If KARIANA is misbehaving, create a support bundle — a single zip with logs, versions, and system info, automatically scrubbed of secrets.

    From inside the editor: open the KARIANA chat and ask it to export a support bundle.

    If the editor will not launch: double-click kariana-support.py in the plugin's Content/Python folder (or run python -m support from that folder).

    Either way a file like kariana-support-20260525-101500.zip appears on your Desktop. Email the whole zip to hello@kariana.ai (offline clients can copy it to a USB drive). It never contains your license token or API keys; open summary.txt inside the zip to see exactly what is included.
