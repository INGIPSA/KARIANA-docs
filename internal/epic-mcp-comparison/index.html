    Epic UE 5.8 MCP Plugins vs. KARIANA K9 — Comparison & Backport Plan#

    Author: KARIANA Team
    Date: 2026-05-03
    Status: Internal — do not distribute

    1. Executive Summary#

    Epic shipped two experimental MCP-related plugins in the UE 5.8 dev tree: a server-side plugin (ModelContextProtocol) that exposes engine tools over HTTP/SSE, and a client-side adapter (MCPClientToolset) that lets the editor consume external MCP servers. KARIANA K9 predates both by roughly a year and covers a much wider tool surface (300+ tools vs. Epic's handful of reflection-derived tools), but it uses a lower-level transport (raw TCP socket on port 9877) and lacks several protocol-layer features that Epic has now standardised. The recommended path for UE 5.8 is a thin FToolset interop shim that feeds KARIANA's existing socket dispatcher through Epic's ToolsetRegistry, letting Epic's HTTP MCP server auto-expose all KARIANA tools with zero schema re-authoring. For the 5.7 production line, a targeted set of backports — primarily MCP protocol-version negotiation, SSE progress streaming, and DNS-rebinding protection — will close the most important reliability gaps at low engineering cost.

    3. What We Adopted into KARIANA 5.8#

    The UE 5.8 port introduces a ToolsetRegistry interop layer that bridges KARIANA's socket dispatcher into Epic's plugin ecosystem without replacing it.

    The FToolset Shim#

    A new C++ class UKarianaToolsetDefinition (planned path: Source/KARIANAEditor/Public/Toolsets/KarianaToolsetDefinition.h) will subclass UToolsetDefinition and annotate its callable functions with UFUNCTION(meta=(AICallable)). Internally, each UFUNCTION stub forwards the call synchronously to the existing KARIANA socket dispatcher, waits for the response_dict entry, and returns the JSON result as a FString.

    Schema generation is handled by Epic's reflection path — the UPARAM(meta=(AIDescription="...")) macro on each function parameter replaces the hand-authored Python dicts in Content/Python/handlers/. This gives KARIANA cooked-platform schema support (Epic's FModelContextProtocolFunctionMetaData USTRUCT cache) for free.

    Registration Flow#

    PostEngineInit
  └─ UKarianaToolsetDefinition::RegisterWithSubsystem()
       └─ UToolsetRegistrySubsystem::RegisterToolset(this)
            └─ IModelContextProtocolModule (ModelContextProtocolEditor adapter)
                 └─ auto-exposes all KARIANA tools via HTTP GET /mcp (port 8000)

    UToolsetRegistrySubsystem fires notifications/tools/list_changed when KARIANA tools are hot-reloaded (i.e., when handlers/ Python files change and the daemon restarts), keeping connected clients in sync without a full editor restart.

    What Is Not Replaced#

    The Python socket server (port 9877), the REGISTER_KARIANA_COMMAND C++ registry, the backend factory, and the Gradio admin dashboard all remain unchanged. The FToolset shim is an additional exposure path, not a replacement. Clients that already connect directly to port 9877 (e.g., the kariana-remote Node.js bridge) continue to work without modification.

    4. Recommended Backports to the 5.7 Line#

    Items are prioritised by reliability impact relative to engineering effort. Items that can be implemented entirely in Python or in the existing UnrealMCPBridge module are preferred because they ship without a C++ rebuild.

    P0 — Critical / Ship Before Next Public Release#

    # Epic Feature KARIANA Files to Touch Effort User-Facing Payoff
    P0-1 DNS-rebinding Origin guard on the HTTP endpoint Content/Python/mcp_server.py (add Host: header check on every request; reject non-localhost / non-127.0.0.1 Origins) S Closes a known lateral-movement attack vector that Epic explicitly addressed; required for any public-facing Claude Desktop config
    P0-2 MCP protocol-version negotiation (initialize handshake with protocolVersion field) Content/Python/mcp_server.py — parse protocolVersion in initialize handler; respond with highest mutually supported version; return LATEST_PROTOCOL_VERSION constant S Claude Desktop 1.x and Cursor enforce version negotiation; without it, connections silently fail after client upgrades
    P0-3 SSE progress heartbeats during long-running tool calls Content/Python/mcp_server.py — emit event: progress lines with {"progress": N, "total": N} during multi-step handlers (BlueprintLisp compilation, HLOD generation, navmesh rebuild) M Eliminates client-side timeouts on 30+ second operations; Claude Desktop shows a live progress bar

    P1 — High Value / Next Sprint#

    # Epic Feature KARIANA Files to Touch Effort User-Facing Payoff
    P1-1 Deferred tool loading (list_toolsets / load_toolset meta-tools) Content/Python/mcp_server.py + Content/Python/backends/tool_selector.py — expose the 30 existing tool categories as lazy toolsets; send only the active-category subset until load_toolset is called M Reduces tools/list payload from ~120 KB to ~4 KB for small-context models (Qwen3-8B, Haiku); directly improves latency and context-window headroom on every query
    P1-2 notifications/tools/list_changed broadcast Content/Python/mcp_server.py — watch handlers/ directory via watchdog; emit notification on file change S Clients pick up new KARIANA tools without reconnecting; important during active tool development sessions
    P1-3 Per-client session isolation Content/Python/mcp_server.py — assign a UUID per connection; scope command_queue entries to session ID; prevents response cross-talk when two AI clients connect simultaneously M Unblocks multi-agent workflows (e.g., one agent doing scene layout while another iterates blueprints)

    5. What KARIANA Does Better Than Epic Today#

    This is not a criticism of Epic's plugins — they are experimental and deliberately minimal. It is an honest statement of where KARIANA provides value that Epic does not.

    Tool breadth. Epic's ModelContextProtocol plugin ships with a small set of reflection-derived tools from existing UBlueprintFunctionLibrary callables. KARIANA has 300+ hand-crafted tools across 30 categories including PCG graph authoring, foliage painting, Take Recorder control, physics simulation triggers, camera rail animation, and World Partition streaming — none of which Epic exposes.

    BlueprintLisp DSL. Epic has no equivalent. The KARIANA KarianaLispParser + KarianaBlueprintLispConverter pipeline lets an AI create a complete, compiled Blueprint graph — variables, events, branches, function calls — in a single tool call instead of 25+ sequential add_node / connect_pins calls. This is the single largest latency reduction for Blueprint-heavy workflows.

    Multi-backend AI routing. Epic's plugin is transport-only; it has no opinion on which AI model executes the tools. KARIANA's backend factory (Content/Python/backends/factory.py) supports Claude Code Bridge, AWS Bedrock (Qwen3/Claude via Lambda), LM Studio (local OpenAI-compatible), and Ollama — all switchable at runtime from Project Settings with no code changes.

    Editor Event Queue. Epic's analytics integration is fire-and-forget. KARIANA's KarianaEventQueue is a thread-safe ring buffer that AI agents can poll to learn what the human editor just did (selection_changed, map_opened, blueprint_compiled), enabling reactive AI assistance without the AI needing to re-query the entire scene state.

    Skill recording. KARIANA records multi-step editor workflows into replayable skill files (Content/Python/skills/), which can be triggered by name via a single execute_skill tool call. Epic has no equivalent concept.

    Gradio admin dashboard. The Content/Python/admin_dashboard/app.py dashboard provides live tool-category filtering, model selection, and connection testing in a browser UI. Epic's config surface is limited to INI settings and console commands.

    6. Coexistence in the Beta58 Project#

    When the UE 5.8 port runs alongside both Epic plugins in a test project, the resulting topology is:

    AI Client (Claude Desktop / Cursor / VS Code)
        │
        │  HTTP POST /mcp  (port 8000)
        ▼
┌────────────────────────────────────────────────────────┐
│  Epic ModelContextProtocol plugin (port 8000)          │
│  ┌──────────────────────────────────────────────────┐  │
│  │  ToolsetRegistry                                 │  │
│  │  ┌──────────────────────────────────────────┐   │  │
│  │  │  UKarianaToolsetDefinition (5.8 shim)    │   │  │
│  │  │  → KARIANA socket dispatcher (port 9877) │   │  │
│  │  └──────────────────────────────────────────┘   │  │
│  │  (+ any other FToolset subclasses Epic ships)   │  │
│  └──────────────────────────────────────────────────┘  │
└────────────────────────────────────────────────────────┘

Epic MCPClientToolset plugin
  → connects outbound to external MCP servers (e.g. filesystem, web search)
  → feeds their tools back into ToolsetRegistry alongside KARIANA tools
  → same single HTTP endpoint at port 8000 surfaces everything

KARIANA Python socket server (port 9877)
  → still accepts direct connections from kariana-remote Node.js bridge
  → still accepts direct connections from Bedrock daemon / LM Studio / Ollama
  → shim and direct path share the same command_queue / response_dict

    There is a single MCP endpoint for AI clients (http://localhost:8000/mcp). All 300+ KARIANA tools appear there via the UKarianaToolsetDefinition shim. Any tools that Epic's MCPClientToolset fetches from external servers also appear at that same endpoint. AI clients do not need to know that two separate plugins and a Python daemon are involved.

    Port 9877 remains open for non-HTTP consumers (kariana-remote, daemon backends). No port conflict exists because Epic uses 8000 and KARIANA uses 9877 by default.

    The ModelContextProtocol.GenerateClientConfig console command will write a single config block pointing at port 8000 that covers everything, replacing the current need to hand-edit .mcp.json entries for port 9877.

    7. Open Questions and Risks#

    # Question / Risk Severity Notes
    R-1 ToolsetRegistry API stability. Engine/Plugins/Experimental/Toolsets/ is marked Experimental in 5.8; its public API may change between 5.8 drops before GA. The UKarianaToolsetDefinition shim could break silently. Medium Pin to a specific 5.8 changelist for the Beta58 branch; add a static_assert on the IToolsetRegistry vtable size as a build-time canary.
    R-2 Schema migration cost for P2-1 (structured output schemas). Adding output_schema to all ~200 handler files is mechanical but risky: a malformed schema silently degrades AI tool-use quality. High Do not ship P2-1 without an automated schema validator in CI (scripts/validate_tool_schemas.py).
    R-3 Session isolation (P1-3) and the response_dict design. The current response_dict keyed by integer counter will need to be re-keyed by (session_id, command_id) tuple. Any handler that directly reads response_dict by integer (there are several in Content/Python/handlers/) will need updating. Medium Audit all direct response_dict accesses before merging P1-3; it is not a one-file change.
    R-4 DNS-rebinding guard (P0-1) breaks internal CI runners. If a CI runner hits the MCP server from a non-localhost IP (e.g., a sidecar container), the Origin check will reject it. Low Add a KARIANA_MCP_ALLOW_ORIGINS env var override for CI environments; default to strict localhost-only.
    R-5 OAuth2 in MCPClientToolset (Epic outbound client) is not yet needed by KARIANA. KARIANA does not currently consume external MCP servers. If the team adds web-search or filesystem MCP servers as context sources, OAuth2 config becomes relevant — but Epic's FMCPServerConfig handling it means KARIANA does not need to implement it. Low Track, do not act.
    R-6 Dual exposure (port 8000 via shim + port 9877 direct) means tool schemas can diverge. If a Python handler description is updated but the UFUNCTION AIDescription annotation is not, the two surfaces describe the same tool differently. Medium Add a CI check that compares tools/list from both surfaces and fails on any description mismatch.
    R-7 BlueprintLisp DSL has no equivalent path through Epic's reflection-only schema model. The DSL takes a freeform string, not a typed struct. The shim will need to expose it as UPARAM(meta=(AIDescription="Lisp expression string")) with a hand-written description — which is fine, but it means the DSL tools will not benefit from Epic's USTRUCT cache. Low Acceptable trade-off; document it in the shim header.

    End of report. For implementation questions, start with Source/KARIANAEditor/ for the 5.8 shim and Content/Python/mcp_server.py for all 5.7 backports.
