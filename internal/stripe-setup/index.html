    Stripe Licensing Setup Guide#

    This document covers the one-time Stripe configuration needed to power KARIANA's licensing system.

    Architecture#

    User → kariana.ai/pricing → Stripe Checkout → Webhook → Lambda → DynamoDB
                                                         ↓
                                                   API Key + Email → User
                                                         ↓
UE Plugin → POST /v1/validate (Bearer sk_live_xxx) → Lambda → DynamoDB lookup
                                                         ↓
                                                   { valid, plan, seats, entitlements }

    1. Create Products#

    In the Stripe Dashboard, create these products:

    Product Metadata kariana_plan Monthly Price Yearly Price
    KARIANA Solo solo $159/seat/mo $1,590/seat/yr
    KARIANA Pro pro Custom Custom
    KARIANA Enterprise enterprise Custom Custom

    Important: Set the kariana_plan metadata key on each product — the webhook reads this to determine the license tier.

    Each price should use per-seat (metered) pricing with usage_type: licensed.

    2. Create Entitlement Features#

    Using the Stripe CLI or API:

    # Core features
stripe entitlements features create --name="AI Assistant Access" --lookup-key=ai_assistant
stripe entitlements features create --name="Blueprint Lisp DSL" --lookup-key=blueprint_lisp
stripe entitlements features create --name="Team Management" --lookup-key=team_management
stripe entitlements features create --name="NDA Mode" --lookup-key=nda_mode
stripe entitlements features create --name="Priority Support" --lookup-key=priority_support

    Then attach features to products:

    # Solo gets ai_assistant + blueprint_lisp
stripe products create_feature prod_SOLO --entitlement-feature=feat_ai_assistant
stripe products create_feature prod_SOLO --entitlement-feature=feat_blueprint_lisp

# Pro gets all Solo features + team_management + nda_mode
stripe products create_feature prod_PRO --entitlement-feature=feat_ai_assistant
stripe products create_feature prod_PRO --entitlement-feature=feat_blueprint_lisp
stripe products create_feature prod_PRO --entitlement-feature=feat_team_management
stripe products create_feature prod_PRO --entitlement-feature=feat_nda_mode

# Enterprise gets everything
stripe products create_feature prod_ENTERPRISE --entitlement-feature=feat_ai_assistant
stripe products create_feature prod_ENTERPRISE --entitlement-feature=feat_blueprint_lisp
stripe products create_feature prod_ENTERPRISE --entitlement-feature=feat_team_management
stripe products create_feature prod_ENTERPRISE --entitlement-feature=feat_nda_mode
stripe products create_feature prod_ENTERPRISE --entitlement-feature=feat_priority_support

    Note: lookup_key cannot be changed after creation. Plan feature assignments carefully.

    3. Configure Customer Portal#

    In Stripe Dashboard > Settings > Billing > Customer Portal:

    • Subscription updates: Enable, allow price and quantity changes
    • Proration behavior: Create prorations (charge immediately on upgrade)
    • Products: Add Solo, Pro, Enterprise with their monthly/yearly prices
    • Quantity limits: Set min=1, max=100 seats
    • Subscription cancellation: Enable, set to cancel at period end
    • Invoice history: Enable

    4. Set Up Webhook#

    In Stripe Dashboard > Developers > Webhooks:

    Endpoint URL: https://api.kariana.ai/v1/webhooks/stripe
    (This is the API Gateway URL from terraform output webhook_url)

    Events to listen for: - checkout.session.completed - customer.subscription.created - customer.subscription.updated - customer.subscription.deleted - invoice.paid - invoice.payment_failed - entitlements.active_entitlement_summary.updated

    Copy the webhook signing secret (whsec_...) for the Terraform deployment.

    5. Deploy Infrastructure#

    cd infrastructure/licensing

# Install dependencies and build
npm install
npm run package

# Deploy with Terraform
cd terraform
terraform init
terraform apply \
  -var="stripe_secret_key=sk_live_..." \
  -var="stripe_webhook_secret=whsec_..." \
  -var="resend_api_key=re_..." \
  -var="stripe_price_solo_monthly=price_..." \
  -var="stripe_price_solo_yearly=price_..." \
  -var="stripe_price_pro_monthly=price_..." \
  -var="stripe_price_pro_yearly=price_..."

    Terraform outputs: - api_url — Base URL for the licensing API - webhook_url — URL to configure in Stripe Dashboard - validate_url — URL the UE plugin uses for license checks

    6. Environment Variables#

    Variable Description Where
    STRIPE_SECRET_KEY Stripe secret key (sk_live_...) Lambda env
    STRIPE_WEBHOOK_SECRET Webhook signing secret (whsec_...) Lambda env
    RESEND_API_KEY Resend API key for transactional emails Lambda env
    LICENSE_TABLE_NAME DynamoDB table name (auto-set by Terraform) Lambda env
    KARIANA_API_KEY User's API key (alternative to Project Settings) User env
    KARIANA_VALIDATE_URL Override validation endpoint (for testing) User env

    7. Testing#

    Test with Stripe CLI#

    # Forward webhooks to local dev server
stripe listen --forward-to localhost:3000/v1/webhooks/stripe

# Trigger a test checkout
stripe trigger checkout.session.completed

    Test validation endpoint#

    # Valid key
curl -X POST https://api.kariana.ai/v1/validate \
  -H "Authorization: Bearer sk_test_xxx"

# Expected response:
# { "valid": true, "plan": "solo", "seats": 1, "entitlements": ["ai_assistant", "blueprint_lisp"], "email": "user@example.com" }

    Test in Unreal Engine#

    1. Open Project Settings > Plugins > KARIANA Assistant
    2. Paste your API key in the "API Key" field
    3. Restart the editor
    4. Watch for the license validation toast notification

    Security Notes#

    • API keys are stored as SHA-256 hashes in DynamoDB — raw keys are never persisted server-side
    • The raw key is shown to the user exactly once (in the welcome email)
    • Webhook signature verification prevents spoofed events
    • API Gateway uses HTTPS only
    • DynamoDB has point-in-time recovery enabled
    • The UE plugin stores the API key in Config/DefaultEditor.ini (plaintext) — ensure this file is in .gitignore

    Coexistence with Clerk Auth#

    The Stripe API key flow coexists with the existing Clerk OAuth flow:

    • Clerk auth: User signs in via browser → daemon generates signed token → offline for 30 days
    • Stripe API key: User pastes key in Project Settings → plugin validates via HTTP → caches as offline token

    Both flows produce the same local .kariana_token file for offline use. The Stripe flow is preferred for new users; Clerk remains for backward compatibility.
