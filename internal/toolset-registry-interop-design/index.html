    KARIANA ToolsetRegistry Interop — Architecture Design#

    Target: expose KARIANA's 300+ MCP tools through Epic's UE 5.8 official ModelContextProtocol HTTP server (port 8000, /mcp) by registering a single FToolset subclass with the ToolsetRegistry plugin.

    1. New Module Recommendation: KarianaToolsetBridge#

    Recommendation: create a new Editor module, LoadingPhase: PostEngineInit.

    Rationale for not reusing an existing module:

    • UnrealMCPBridge loads at phase Default. UToolsetRegistrySubsystem is a UEditorSubsystem and is not guaranteed initialized until PostEngineInit. Calling RegisterToolset from Default phase will crash on subsystem lookup.
    • GenerativeAISupportEditor already owns the C++ FKarianaCommandRegistry. Adding a ToolsetRegistry concern there violates SRP and creates a circular-dependency risk if KarianaToolsetBridge later depends on UnrealMCPBridge (socket reuse).
    • A dedicated module isolates the Epic API surface. If Epic changes FToolset between UE 5.8 minor versions, only KarianaToolsetBridge.Build.cs updates.
    • The module can be conditionally compiled (#if WITH_EDITOR) and excluded from cooked targets without touching any runtime module.

    2. Class Design#

    2.1 FKarianaToolset : public FToolset#

    File: Source/KarianaToolsetBridge/Public/FKarianaToolset.h

    FString CachedSchemaJson          // populated once at construction, immutable after
FCriticalSection PendingLock      // guards PendingPromises map
TMap<FString, TSharedPtr<TPromise<TValueOrError<FString,FString>>>> PendingPromises

    Toolset name exposed to Epic is "kariana", making descriptors kariana.<tool_name>.

    2.2 GetJsonSchemaInternal() — Recommended: Python via IPythonScriptPlugin, cached at construction#

    Option A (recommended): At construction time, call IPythonScriptPlugin::Get()->ExecPythonCommandEx() to import tool_schema and call extract_tool_schemas(). Translate from KARIANA's OpenAI-function-call format ({type: function, function: {name, description, parameters}}) into the MCP tools/list shape ({tools: [{name, description, inputSchema}]}) inside the same Python invocation. Store the serialized string in CachedSchemaJson. GetJsonSchemaInternal() returns it directly — zero allocation on repeat calls.

    Option B: Derive schemas from FKarianaCommandRegistry::GetAllCommands(). Rejected: the C++ registry only covers high-frequency operations; ~270 Python-only tools would be missing.

    Caching/invalidation: Static for the editor session. Console command kariana.RefreshToolsetSchema re-runs Python extraction and re-registers the toolset for development workflows.

    2.3 ExecuteToolInternal(FString ToolName, FString JsonInput) — Two-tier dispatch#

    Returns TFuture<TValueOrError<FString, FString>>.

    Tier 1 (C++ fast path): If FKarianaCommandRegistry::Get().HasCommand(ToolName), execute via ExecuteCommandJson(ToolName, JsonInput) synchronously. Wrap in a fulfilled TPromise, return its future immediately.

    Tier 2 (Python socket): Else write {"type": ToolName, "params": <parsed>, "request_id": <guid>} to KARIANA's TCP server on port 9877. Steps:

    1. Generate RequestId = FGuid::NewGuid().ToString().
    2. Insert TSharedPtr<TPromise> into PendingPromises[RequestId] under PendingLock.
    3. Non-blocking socket write (any thread).
    4. Socket reader thread (existing FMCPSocketServer worker) matches incoming request_id, fulfills promise, removes from map.
    5. Return future to caller.

    Timeout: 30 seconds (configurable via UKarianaAssistantSettings::ToolExecutionTimeoutSeconds); a periodic FTSTicker fulfills stale promises with an error.

    3. Module Startup Wiring#

    void FKarianaToolsetBridgeModule::StartupModule()
{
    FCoreDelegates::OnPostEngineInit.AddRaw(this, &FKarianaToolsetBridgeModule::OnPostEngineInit);
}

void FKarianaToolsetBridgeModule::OnPostEngineInit()
{
    auto* Subsystem = GEditor->GetEditorSubsystem<UToolsetRegistrySubsystem>();
    if (!Subsystem) return;
    TSharedRef<FKarianaToolset> Toolset = MakeShared<FKarianaToolset>();
    Subsystem->ToolsetRegistry.RegisterToolset(Toolset);
    RegisteredToolset = Toolset;
}

    Optionally, also call IModelContextProtocolModule::GetChecked().OnRefreshTools() to re-add when Epic's MCP module asks for refresh.

    5. Deferred Tool Loading Option (kariana_dispatch)#

    Single meta-tool with tool_name + payload parameters, mirroring Epic's list_toolsets/describe_toolset/load_toolset deferred pattern.

    Pros: minimal schema payload; immune to KARIANA tool churn; matches existing tool_schema.py:get_deferred_loading_discovery_tools(). Cons: destroys discoverability — Epic's UI and any AI client lose tool descriptions. Hides KARIANA's capability from the broader MCP ecosystem.

    Verdict: ship it as a fallback, not the default. When Python schema extraction returns < 50 tools, register kariana_dispatch instead. Setting bForceDispatchMode = true opts in for minimal-footprint deployments.

    6. Coexistence with KARIANA's Existing Socket Server#

    Both transports run simultaneously:

    Transport Port Client
    KARIANA TCP socket 9877 Claude Code Bridge daemon, LM Studio, Ollama, Bedrock backends, kariana-remote
    Epic MCP HTTP 8000 Epic's MCP clients, third-party MCP tools

    FKarianaToolset is an internal client of port 9877 (persistent socket preferred for latency).

    7. Test Strategy#

    New Editor module KarianaToolsetBridgeTests, WITH_AUTOMATION_TESTS only.

    Test A — Schema validation (FToolsetSchemaTest): Construct FKarianaToolset, parse GetJsonSchemaInternal(), assert tools array length > 50, every entry has name/description/inputSchema, get_project_info present.

    Test B — Round-trip execution (FToolExecuteRoundTripTest, [Slow]): Requires socket server. Calls get_project_info (no params) and handshake_test (single string), asserts non-error futures and expected response fields.

    Test C — Integration (FMCPHttpToolsListTest, [RequiresNetwork][Slow]): Requires Epic's MCP server. POST http://localhost:8000/mcp with tools/list, assert at least one tool name starts with kariana., kariana.get_project_info is present.

    9. Risks#

    R1 — FToolset API surface uncertainty (high impact, medium probability) — design built from header summaries; full method signatures need verification against E:\ue5.8-dev source before implementation. Mitigation: pin to a concrete commit hash, add static_assert confirming the base class.

    R2 — Circular module deps (high, low) — KarianaToolsetBridge depends on GenerativeAISupportEditor and UnrealMCPBridge. Reverse direction must remain forbidden. Mitigation: singleton-only access; no headers of KarianaToolsetBridge are included from those modules; document the one-way arrow in Build.cs comments.

    R3 — Python schema extraction timing (medium, medium) — IPythonScriptPlugin may not have unreal module fully ready at PostEngineInit. tool_schema.py:_get_fallback_schemas() activates as fallback. Mitigation: detect fallback (count < 50), log warning, retry after 5s via FTicker.

    R4 — Cooked-platform stripping (low, low) — Editor type module is correctly excluded; verify .uplugin matches pattern of existing Editor modules.

    R5 — Promise fulfillment race on shutdown (medium, low) — unfulfilled TPromise triggers Debug check on destruction. Mitigation: ShutdownModule iterates pending map, fulfills each with "Shutdown" error before socket close.

    R6 — Schema divergence between socket and MCP surfaces — Python tool_schema.py is the single source of truth; if a tool is added but the Python registry isn't refreshed, MCP clients see stale data. Mitigation: console command to re-extract.

    R7 — CI Origin-guard breakage — Epic's DNS-rebinding guard rejects non-localhost Origins. Test C HTTP integration test must use 127.0.0.1 not a hostname.
