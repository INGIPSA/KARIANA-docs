    Swap Manifest v1#

    The KARIANA editor writes a swap manifest to <LocalAppData>/KARiANA/swap-manifest.json immediately before exiting for an auto-update. The bootstrapper (tools/update-bootstrapper/) reads this file as its single source of truth — no command-line state, no environment lookups beyond what the JSON tells it.

    Both sides MUST stay in sync. C++ writer: Source/UnrealAssistantIntegration/Private/Updates/KarianaSwapManifest.cpp. Rust reader: tools/update-bootstrapper/src/manifest.rs.

    Schema#

    {
  "schema": 1,
  "editor_pid": 12345,
  "plugin_dir": "C:/Users/aristide/MyProject/Plugins/KARIANA",
  "staged_zip": "C:/Users/aristide/AppData/Local/KARiANA/pending-update/0.10.4.zip",
  "expected_sha256": "abc123...",
  "rename_suffix": ".old-20260430-153012",
  "relaunch": {
    "enabled": true,
    "executable": "C:/Program Files/Epic Games/UE_5.7/Engine/Binaries/Win64/UnrealEditor.exe",
    "args": ["C:/Users/aristide/MyProject/MyProject.uproject"],
    "working_dir": "C:/Users/aristide/MyProject"
  },
  "log_path": "C:/Users/aristide/AppData/Local/KARiANA/bootstrapper.log",
  "rollback_marker": "C:/Users/aristide/AppData/Local/KARiANA/last-good-version.txt",
  "from_version": "0.10.3",
  "to_version": "0.10.4"
}
    Field Required Meaning
    schema yes Always 1 for this version. Bootstrapper refuses unknown schemas.
    editor_pid yes Editor process ID. Must be > 0 (zero on POSIX matches the whole process group, would silently turn into a guaranteed 30 s timeout). Bootstrapper waits up to 30 s for it to exit before swapping.
    plugin_dir yes Absolute path to the existing Plugins/KARIANA dir to be replaced. Must be a real directory (not a symlink — refused).
    staged_zip yes Absolute path to the verified update zip. Compression methods supported: deflate, bzip2, zstd.
    expected_sha256 yes Exactly 64 lowercase hex characters — SHA-256 of staged_zip. Bootstrapper re-verifies before doing anything destructive.
    rename_suffix yes Suffix appended to old plugin dir. Must start with .old- (both writer and reader enforce this; the prefix is what the plugin's next-launch sweep matches).
    relaunch.enabled yes If true, bootstrapper spawns executable after a successful swap.
    relaunch.executable conditional Required when relaunch.enabled is true. Absolute path.
    relaunch.args conditional Argument list (excluding executable).
    relaunch.working_dir optional If empty, the spawned process inherits the bootstrapper's CWD.
    log_path yes Bootstrapper appends progress to this file. Always written even on success.
    rollback_marker yes On success, bootstrapper writes to_version here. Plugin's next-launch sweep reads this to know the swap completed cleanly.
    from_version informational For logs only.
    to_version informational For logs and rollback_marker content.

    Failure codes#

    The bootstrapper exits non-zero on any failure. Each variant of SwapError corresponds to one of these conditions:

    Variant When it fires State after
    Manifest(...) Manifest file unreadable, malformed JSON, schema != 1, any field validation rejection (zero pid, malformed sha, non-absolute path, ...). Pre-destructive. No rename has happened. Plugin dir intact.
    EditorDidNotExit editor_pid was still alive after 30 s. Pre-destructive.
    StagedZipMissing staged_zip no longer exists when the bootstrapper goes to read it. Pre-destructive.
    ShaMismatch Re-computed SHA-256 of staged_zip doesn't match expected_sha256. Pre-destructive.
    ZipSlip Any zip entry has an absolute path, .. segment, drive-letter prefix, or symlink mode. Pre-destructive.
    PluginDirMissing plugin_dir does not exist (orchestrator should never produce this — defensive). Pre-destructive.
    PluginDirIsSymlink plugin_dir is a symlink (developer setup). Refused so the swap can't follow the link to an unintended target. Pre-destructive.
    UpluginMissingAfterExtract After extraction, KARIANA.uplugin not present. Post-rename, rollback fired. Old dir renamed back to plugin_dir.
    Io(...) Any underlying I/O error during rename, extract, marker write, or relaunch. Mostly post-rename — rollback attempted; check log for which step.
    Zip(...) Zip parse error during validate or extract (e.g., truncated archive). Pre- or post-rename depending on when it fires. Rollback attempted if post.

    Bootstrapper algorithm#

    1. Parse + validate manifest. Reject schema != 1, reject any path containing .., reject relative paths.
    2. Wait for editor exit. Poll editor_pid up to 30 s. If it never exits, abort with editor_did_not_exit (no destructive action taken).
    3. Re-verify SHA-256 of staged_zip against expected_sha256. Mismatch → abort with sha_mismatch.
    4. Validate zip entries without extracting. Reject any entry where the relative path:
    5. Is absolute (starts with /, \, or contains a drive-letter :)
    6. Contains .. segments after normalization
    7. Is a symlink (zip entry external attributes flag the symlink mode bit) These three checks together are the zip-slip guard — sufficient to guarantee no entry can escape the eventual extraction root.
    8. Rename every direct child of plugin_dir to <name><rename_suffix>. If plugin_dir itself is the rename target (typical), rename the whole dir to <plugin_dir><rename_suffix> and recreate plugin_dir empty.
    9. Extract zip into plugin_dir's parent.
    10. Verify the extracted result contains a parseable KARIANA.uplugin. If missing → rollback.
    11. On success:
    12. Write to_version to rollback_marker.
    13. Append OK line to log_path.
    14. If relaunch.enabled, spawn the editor process detached and exit 0.
    15. On any failure between steps 5 and 7:
    16. Delete the partial extraction.
    17. Rename <plugin_dir><rename_suffix> back to plugin_dir.
    18. Append FAIL <reason> to log_path.
    19. Do NOT touch rollback_marker.
    20. Exit non-zero.

    Cleanup#

    The bootstrapper does NOT delete the renamed .old-* files. Doing so would race with any UE process that might still be reading them (Windows file locks released on process exit, but the bootstrapper might run before all handles close). Instead:

    • Plugin KarianaUpdateChecker::Initialize runs a sweep on the next editor launch: anything matching <PluginParentDir>/KARIANA<rename_suffix_glob> is deleted.
    • Stale .old-* is harmless except for disk-space; the sweep is best-effort.

    Rollback semantics#

    If the plugin's first launch after a swap reads rollback_marker and finds it does NOT match the just-loaded KARIANA.uplugin's VersionName, it logs a warning and triggers a telemetry POST (Phase 4). The plugin still loads — we don't bail an editor session over a marker mismatch.

    If the plugin's first launch finds NO rollback_marker but does find a .old-* sibling, it assumes the bootstrapper crashed mid-swap, runs the rename-back recovery, and POSTs a telemetry failure.

    Security notes#

    • Zip integrity: SHA-256 of staged_zip is the only integrity check in v1. A CDN compromise that substitutes a malicious zip with a matching SHA-256 (preimage attack — infeasible in practice for SHA-256) would defeat this. Future hardening: cosign / Authenticode signature verification.
    • Manifest authenticity: The manifest JSON itself is not signed or MAC'd in v1. An attacker with write access to the user's <LocalAppData>/KARiANA/ directory can substitute a crafted manifest pointing the bootstrapper at an arbitrary zip. The SHA-256 still validates the zip body, so the attacker would need both a malicious zip AND its hash, but they could redirect to a zip from any URL the editor reaches. Accepted tradeoff for v1 (local-privilege user, same security boundary as the rest of <LocalAppData>). Future hardening: HMAC the manifest with a per-install key.
    • No elevation: the bootstrapper does not run with elevated privileges. Plugin install paths that require elevation (engine installs) are blocked at FKarianaInstallContext::CanAutoUpdate time and never reach this flow.
    • Write surface: the bootstrapper writes only to plugin_dir, plugin_dir's parent, log_path, and rollback_marker. All other paths are read-only.
