    12. Problems & Issues#

    CRITICAL#

    P1: SKarianaContextBar Has No Brand Colors#

    File: SKarianaContextBar.cpp Issue: All 3 text labels use hardcoded FLinearColor(1.0, 1.0, 1.0, 0.2). Does not include KarianaBrandColors.h. Completely bypasses the theme system. Impact: Theme changes have zero effect on the status bar. Fix: Import brand colors, replace with KarianaBrand::TextTertiary or new dedicated color.

    P2: 8 Hardcoded Icon Opacity Values#

    Files: SKarianaChatPanel.cpp (5 instances), SKarianaContextBar.cpp (3 instances) Issue: FLinearColor(1.0, 1.0, 1.0, 0.2) repeated 8 times for icon dimming. Impact: Cannot change icon brightness via theme. Redundant code. Fix: Add KarianaBrand::IconDimmed to the brand namespace and dispatch table.

    HIGH#

    P3: Dual Source of Truth (C++ + JSON)#

    Files: KarianaBrandColors.h + themes.json Issue: Same 69 colors defined in both files. Must update both when changing colors. Impact: Forgetting one leads to inconsistency. JSON override masks C++ changes silently. Fix: Designate one as canonical source with the other as override/fallback.

    P4: FKarianaMarkdownStyle Name Is Misleading#

    File: KarianaMarkdownStyle.cpp/.h Issue: Contains ALL chat UI brushes (surfaces, bubbles, pills, inputs, avatars, badges) -- not just markdown. Name suggests markdown-only scope. Impact: Developers look for "chat style" or "UI style" and can't find it. Fix: Rename to FKarianaUIStyle or FKarianaChatStyle.

    P5: No Semantic Token Layer#

    Issue: Colors named by appearance (Pink, BgRaised) not by role (AccentPrimary, SurfaceCard). Impact: Theme customization is brittle. Can't answer "what color is the primary action?" without reading code. Fix: Add KarianaToken namespace with role-based references to brand colors.

    P16: bIsProcessing Duplicated Across 3 Widgets#

    Files: SKarianaChatInput.h, SKarianaContextBar.h, SKarianaStatusOverlay.h Issue: Three separate bIsProcessing flags, all push-updated by the panel via SetProcessing(). No single authoritative source. Impact: Easy to miss a widget when adding new processing-dependent behavior. State can drift. Fix: Introduce shared observable state (e.g., FKarianaUIState struct with OnChanged delegate).

    P17: ~195 Hardcoded Layout Magic Numbers#

    Files: All 17 widget .cpp files (worst: SKarianaChatPanel.cpp 41, SKarianaUserInputPrompt.cpp 22, SKarianaStepsWidget.cpp 20) Issue: Spacing, sizing, font sizes, radii, and padding are literal numbers scattered across the codebase. Impact: Changing "toolbar height" means finding the right HeightOverride(32) among 25+ similar calls. Fix: Create KarianaLayoutConstants.h with named constants.

    MEDIUM#

    P6: Welcome Screen Card Uses Hardcoded Color#

    File: SKarianaWelcomeScreen.cpp:63 Issue: Card brush uses FLinearColor(0.027, 0.027, 0.030) instead of KarianaBrand::BgPrompt. Fix: Use KarianaBrand::BgPrompt or define a new CardBg.

    P7: Drop Target Uses Non-Theme Blue#

    File: SKarianaDropTarget.cpp:180 Issue: FLinearColor(0.2, 0.4, 0.8, 0.5) -- arbitrary blue contradicts theme. Fix: Add KarianaBrand::DropHighlight.

    P8: Input Border Color Hardcoded in StyleSet#

    File: KarianaMarkdownStyle.cpp:304 Issue: FLinearColor(0.851, 0.851, 0.851, 0.09) bypasses brand system. Fix: Add KarianaBrand::InputBorderColor.

    P9: Duplicate Header File#

    Files: Private/Widgets/KarianaMarkdownStyle.h AND Public/Widgets/KarianaMarkdownStyle.h Issue: Two copies with slightly different contents. ODR hazard. Fix: Delete Public/Widgets/KarianaMarkdownStyle.h.

    P10: themes.json in Wrong Location#

    File: installers/gradio-app/themes.json Issue: Theme data buried in installer directory. Fix: Move to Content/Config/themes.json.

    P11: Linear-Space vs sRGB Confusion in Comments#

    File: KarianaBrandColors.h Issue: Hex comments reference sRGB but FLinearColor is linear-space. Fix: Fix comments to show correct sRGB equivalents.

    P18: FOnHistoryPanelClosed Delegate Declared But Never Wired#

    File: SKarianaHistoryPanel.h Issue: Dead delegate -- declared but never bound at the construction site. Fix: Either wire it or remove the declaration.

    P19: Hub Overload in SKarianaChatPanel#

    File: SKarianaChatPanel.cpp Issue: Panel handles ~14 inbound delegates and ~10 outbound targets. Session management, undo/redo, rendering, streaming, mode switching, history, attachments, plan approval -- all in one class. Impact: Large file, difficult to navigate, single bottleneck for every change. Fix: Extract sub-controllers (FKarianaMessageController, FKarianaSessionController, etc.).

    LOW#

    P12: BgInput Same as BgBase#

    Issue: Identical values. Redundant color. Fix: Differentiate or remove the duplicate.

    P13: Bunting Color Appears Unused#

    Issue: Defined but no widget references it. Fix: Remove or document intended use.

    P14: History Panel Uses Constructor Transparent#

    File: SKarianaHistoryPanel.cpp:196 Issue: FLinearColor(0,0,0,0) instead of FLinearColor::Transparent. Fix: Use FLinearColor::Transparent.

    P15: Mixed Runtime Theme Update Support#

    Issue: Colors baked at widget construction. Reinitialize() requires closing the chat tab. Fix: Use cached color store + OnThemeChanged delegate pattern (see refactor plan).
