    3. Layout & Spacing Details#

    3.1 Per-Widget Layout Specs#

    Header Bar#

    • Container: SBorder(KarianaBgRaised) + SBox[Height=40] + padding 4
    • Menu icon: SBox[24x24] + SImage(Kariana.Icon.Menu)
    • Model combo: FillWidth=1.0, HAlign=Center, flat transparent style
    • Status dot: SBox[8x8], color bound to connection state

    Toolbar#

    • Container: SBorder + SBox[Height=32]
    • Separators: SBox[Width=1, Height=20]
    • Icon buttons: SImage with ColorAndOpacity = FLinearColor(1,1,1,0.2) (hardcoded)
    • Spacer: FillWidth=1.0 via SNullWidget

    Welcome Screen#

    • Title padding: FMargin(12, 20, 12, 8)
    • Card padding: FMargin(12, 2) per slot
    • Card border: FSlateRoundedBoxBrush(color, radius=10), inner padding FMargin(15, 10)
    • Card text: Regular 10pt, TextPrimary
    • Edit icon: SBox[16x16], opacity 0.2

    Chat Input#

    • Outer: SBox padding FMargin(8, 4, 8, 8)
    • Border: FSlateRoundedBoxBrush(BgRaised, radius=5) + dynamic border color (focus=Pink 1.5px, blur=gray 1px)
    • Border inner padding: FMargin(8, 6)
    • Logo: SBox[27x27], padding FMargin(4, 0, 4, 0)
    • TextBox: FMargin(8, 8) padding, auto-wrap, Enter=send, Shift+Enter=newline
    • Action button pill: SBox[32x32], KarianaPillStandard brush (pink rounded)

    Mode Selector#

    • Container: SBorder(KarianaModeContainer, radius=5, BorderDefault border), padding 3
    • Height: SBox[Height=32]
    • Pill slots: FillWidth=1.0, padding FMargin(2, 0)
    • Pill border: FSlateRoundedBoxBrush, radius 12 (standard) or 3 (active/inactive)
    • Active label: Bold 9pt, TextInverse (black on white bg)
    • Inactive label: Regular 9pt, TextTertiary

    User Message#

    • Container: SBox[HAlign=Right, Padding=8,4]
    • Max width: MaxDesiredWidth=350
    • Pill: SBorder(KarianaUserPillBg, radius=14, Padding=12,8)
    • Text: Regular 10pt, TextPrimary, readonly multi-line

    Assistant Message#

    • Container: SBox[HAlign=Left, Padding=12,4]
    • Content: SKarianaMarkdownRenderer (full width, no max constraint)
    • Stats bar: Regular 8pt, TextTertiary, visibility collapsed until complete
    • Action buttons: Copy (14x14 icon), Thumbs up/down (Unicode chars, 10pt)

    Steps Widget#

    • Container: SBox[HAlign=Left, Padding=8,4,40,4] (40px right padding)
    • Thinking dot: 7pt TextTertiary, "KARIANA is thinking..." 9pt TextSecondary
    • Throbber: SCircularThrobber(Radius=4) in SBox[12x12]
    • Step rows: 2px accent bar (left edge), 9pt label, 8pt detail, Mono 7pt timing
    • Step icon status: Completed=StatusConnected, Failed=StatusError, Cancelled=TextTertiary
    • Toggle: 8pt TextTertiary, "Show/Hide N activities"
    • Streaming preview: Italic 8pt, TextTertiary, 120 char max

    Context Bar#

    • Container: SBorder(KarianaBgBase, Padding=8,4)
    • All text: Regular 8pt, FLinearColor(1,1,1,0.2) (hardcoded, not brand)
    • Spinner: SCircularThrobber(Radius=6), visible when processing
    • Slot gaps: 12px right padding between items

    History Panel#

    • Back button: SBox[32x32], Unicode arrow, Regular 18pt
    • Title: Bold 16pt, TextPrimary, padding FMargin(16, 8, 16, 12)
    • Section headers: Bold 9pt, TextTertiary, padding FMargin(12, 10, 12, 4)
    • Entry: padding FMargin(16, 8), title Regular 11pt, subtitle Regular 9pt
    • Active entry: BgElevated background, others transparent
    • Delete button: SBox[16x16], Trash icon, TextTertiary

    Attachment Bar#

    • Container: SBorder(BgRaised, Padding=4,2), collapses when empty
    • Chips: SBorder(BgElevated, Padding=4,2) with icon (12x12) + name (9pt) + remove button
    • Wrap flow: SWrapBox(UseAllottedSize=true)

    Processing Log#

    • Wrapper: SExpandableArea (gated on bShowProcessingLog) → SBox[MaxDesiredHeight=180]
    • Entry list: SListView, row padding FMargin(4, 2)
    • Timestamp: Mono 9pt, TextTertiary
    • Message: Regular 9pt, color varies by level (Info=TextPrimary, Success=Green, Warning=Yellow, Error=Red, Step=Pink)
    • Header: entry count (9pt TextTertiary) + Clear button

    Status Overlay#

    • Title: Bold 12pt, "KARIANA"
    • Status icon colors: Disabled=TextTertiary, Processing=Pink, Ready=StatusConnected
    • Model selector: SComboBox, visibility gated on CanChangeModel
    • Spinner: SCircularThrobber(Radius=8), hidden when not processing

    Architecture#

│                        COLOR SOURCES                                │

            │                             │
            │    ┌────────────────────────┐│
            └───>│  KarianaBrandTheme.cpp ││
                 │  ApplyTheme()          ││
                 │  ─ Dispatch table maps │◄┘
                 │    JSON keys → ptrs    │
                 │  ─ Overwrites inline   │

            ┌───────────────┴───────────────┐
            │                               │

│                       │     │                          │

└───────────────────────┘     └──────────────────────────┘

    Data Flow#

    1. Default colors → inline FLinearColor globals in KarianaBrandColors.h (69 colors)
    2. On startup → KarianaBrandTheme::ApplyTheme("KARIANA Dark") reads themes.json
    3. Dispatch table → 69-entry map of JSON key strings to pointers to those inline globals
    4. Overwrites → JSON values replace inline globals in-place (same linear-space format)
    5. Fallback → if themes.json missing, hardcoded defaults remain (always works)
    6. Consumption → two patterns: direct KarianaBrand::XYZ reads, or FKarianaMarkdownStyle::Get() brushes

    File Map#

    File Role
    Public/KarianaBrandColors.h 69 color definitions (inline globals, namespace KarianaBrand)
    Public/KarianaBrandTheme.h Theme API: ApplyTheme(), LoadThemeFromConfig(), GetAvailableThemeNames()

    9. State Management & Behavior#

    9.1 Connection States#

    • Status dot in header: green (StatusConnected), yellow (StatusWarning), red (StatusError)
    • Status overlay icon (orphaned — SKarianaStatusOverlay is never instantiated): gray (TextTertiary=disabled), pink (Pink=processing), green (StatusConnected=ready)

    9.2 Processing States#

    • bIsProcessing flag in ChatInput, ContextBar, StatusOverlay
    • Input: disabled text field, stop icon replaces send icon
    • Context bar: spinner visible, "Processing..." text
    • Steps widget: thinking bubble visible, streaming preview active

    Note: bIsProcessing is duplicated across three separate widgets (SKarianaChatInput, SKarianaContextBar, SKarianaStatusOverlay). All three are push-updated by the panel via SetProcessing() from OnStreamingStateChanged. There is no single authoritative processing flag — the panel fans out to each child manually.

    9.3 Mode System#

    • 3 modes: Validate (Plan), Teach, Create (BypassPermissions)
    • Active pill: white bg (BgModeActive), bold black text (TextInverse)
    • Inactive pill: transparent, regular dim text (TextTertiary)
    • Mode accent colors only used for text emphasis in mode selector, not widespread

    9.4 Font Scaling#

    • SDPIScaler wraps entire panel, controlled by FontScale member
    • CTRL+scroll adjusts 1.0-2.0 range, applied per-frame via lambda
    • MarkdownRenderer also has SetFontScale() for its own SDPIScaler

    9.5 Streaming#

    • SKarianaChatMessage::UpdateContent() feeds new text to markdown renderer
    • SKarianaMarkdownRenderer::SetContent(text, isStreaming=true) does incremental render
    • SKarianaStepsWidget shows streaming preview (120 char, word-boundary truncation)
    • Authoritative streaming state lives in FKarianaChatSession::IsStreaming(), broadcast via OnStreamingStateChanged

    9.6 Undo/Redo#

    • Dual stacks: ConversationUndoHistory, ConversationRedoBuffer
    • Conversation-level undo (not individual edits)
    • Separate from UE editor transaction history

    12. Problems & Issues#

    P1: CRITICAL — SKarianaContextBar Has No Brand Colors#

    File: SKarianaContextBar.cpp Issue: All 3 text labels use hardcoded FLinearColor(1.0, 1.0, 1.0, 0.2). Does not include KarianaBrandColors.h. Completely bypasses the theme system. Impact: Theme changes have zero effect on the status bar. Fix: Import brand colors, replace with KarianaBrand::TextTertiary or new dedicated color.

    P2: CRITICAL — 8 Hardcoded Icon Opacity Values#

    Files: SKarianaChatPanel.cpp (5 instances), SKarianaContextBar.cpp (3 instances) Issue: FLinearColor(1.0, 1.0, 1.0, 0.2) repeated 8 times for icon dimming. Impact: Cannot change icon brightness via theme. Redundant code. Fix: Add KarianaBrand::IconDimmed to the brand namespace and dispatch table.

    P3: HIGH — Dual Source of Truth (C++ + JSON)#

    Files: KarianaBrandColors.h + themes.json Issue: Same 69 colors defined in both files. Must update both when changing colors. Impact: Forgetting one leads to inconsistency. JSON override masks C++ changes silently. Fix: Designate one as canonical source with the other as override/fallback.

    P4: HIGH — FKarianaMarkdownStyle Name Is Misleading#

    File: KarianaMarkdownStyle.cpp/.h Issue: Contains ALL chat UI brushes (surfaces, bubbles, pills, inputs, avatars, badges) — not just markdown. Name suggests markdown-only scope. Impact: Developers look for "chat style" or "UI style" and can't find it. New brushes get added to wrong places. Fix: Rename to FKarianaUIStyle or FKarianaChatStyle.

    P5: HIGH — No Semantic Token Layer#

    Issue: Colors named by appearance (Pink, BgRaised) not by role (AccentPrimary, SurfaceCard). Changing brand accent from pink requires auditing every Pink usage. Impact: Theme customization is brittle. Can't answer "what color is the primary action?" without reading code. Fix: Add KarianaToken namespace with role-based references to brand colors.

    P6: MEDIUM — Welcome Screen Card Uses Hardcoded Color#

    File: SKarianaWelcomeScreen.cpp:63 Issue: Card brush uses FLinearColor(0.027, 0.027, 0.030) instead of KarianaBrand::BgPrompt (0.065, 0.065, 0.070). Different values. Impact: Welcome cards don't update with theme changes. Color doesn't match the defined BgPrompt. Fix: Use KarianaBrand::BgPrompt or define a new CardBg if the different shade is intentional.

    P7: MEDIUM — Drop Target Uses Non-Theme Blue#

    File: SKarianaDropTarget.cpp:180 Issue: FLinearColor(0.2, 0.4, 0.8, 0.5) — arbitrary blue that contradicts the dark neutral theme. Impact: Drag-drop highlight looks out of place, can't be themed. Fix: Add KarianaBrand::DropHighlight with a theme-appropriate color (pink accent or neutral).

    P8: MEDIUM — Input Border Color Hardcoded in StyleSet#

    File: KarianaMarkdownStyle.cpp:304 Issue: FLinearColor(0.851, 0.851, 0.851, 0.09) for input border bypass brand system. Impact: Can't theme the input border. Fix: Add KarianaBrand::InputBorderColor.

    P9: MEDIUM — Duplicate Header File#

    Files: Private/Widgets/KarianaMarkdownStyle.h AND Public/Widgets/KarianaMarkdownStyle.h Issue: Two copies of the class declaration with slightly different contents. The .cpp includes the Private one. Impact: Public copy is stale. Confusion about which to include. Fix: Delete Public/Widgets/KarianaMarkdownStyle.h.

    P10: MEDIUM — themes.json in Wrong Location#

    File: installers/gradio-app/themes.json Issue: Theme data buried in installer directory. Path resolved via ResolvePluginRoot() + hardcoded relative path. Impact: Fragile path, semantically wrong location (themes != installers). Fix: Move to Content/Config/themes.json or Config/themes.json.

    P11: MEDIUM — Linear-Space vs sRGB Confusion in Comments#

    File: KarianaBrandColors.h Issue: Hex comments (e.g., // #1a1a1a) reference sRGB values, but FLinearColor stores linear-space. The hex doesn't match what renders on screen. Impact: Confusion when translating Figma designs (Figma uses sRGB hex). Example: BgBase = (0.040, 0.040, 0.040) renders as ~#363636, not #1A1A1A as commented. Fix: Fix comments to show correct sRGB equivalents, or note gamma conversion.

    14. How-To Reference#

    Change a color value#

    1. Edit KarianaBrandColors.h — change the inline FLinearColor default
    2. Edit themes.json — change the matching [R, G, B] array
    3. Rebuild in Rider
    4. If the color is used in a KarianaMarkdownStyle brush, close and reopen the chat panel

    Add a new color#

    1. Add inline FLinearColor NewColor(R, G, B); to KarianaBrandColors.h
    2. Add Table.Add(TEXT("NewColor"), &KarianaBrand::NewColor); to dispatch table in KarianaBrandTheme.cpp
    3. Add "NewColor": [R, G, B] to themes.json
    4. Use in widgets: KarianaBrand::NewColor or create a brush in KarianaMarkdownStyle.cpp

    Translate Figma hex to FLinearColor#

    Linear = pow(sRGB_byte / 255.0, 2.2)
    Figma Hex Linear R, G, B
    #1A1A1A 0.010, 0.010, 0.010
    #242424 0.017, 0.017, 0.017
    #3C3C3C 0.045, 0.045, 0.045
    #45454D 0.058, 0.058, 0.073
    #555555 0.090, 0.090, 0.090
    #999999 0.318, 0.318, 0.318
    #EBEBEB 0.835, 0.835, 0.835
    #FF7EDC 1.000, 0.208, 0.718

    1. Place PNG at Content/Slate/Icons/YourIcon.png

      Style->Set("Kariana.Icon.YourIcon", new FSlateImageBrush(
    FPaths::Combine(IconsDir, TEXT("YourIcon.png")), FVector2D(W, H)));
    3. Use in widget: FKarianaMarkdownStyle::Get().GetBrush("Kariana.Icon.YourIcon")
